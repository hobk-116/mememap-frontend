This is a historical record of the foundation refactor on 02/10/2026 and earlier UI work. Results below belong to their recorded period and do not verify new changes. Current requirements are in [AGENTS.md](../../../AGENTS.md) and the [testing guide](../TESTING.md).

## Foundation refactor — 02/10/2026

The six steps were completed in order before building community:

| Step | Result |
| --- | --- |
| 1. Standardize regressions | Corrected old Menu/Admin and pin-geometry assumptions; added a browser runner with separate disposable data for each suite. |
| 2. Separate backend business logic | `server.py` handles HTTP; `mememap/` contains account, profile, pin and moderation services. `Application` supports direct tests and independent instances. |
| 3. Migrations, configuration and media | Versioned migrations, schema rollback and copying images before commit; environment-based database/uploads/cookie settings; checks for cleanup and data preservation after failures. |
| 4. Shared API client | Home, map and Admin use `api.js`; errors preserve code/status/details, with consistent expired-session and cancellation handling. |
| 5. Split map responsibilities | Separate pins, composer, profile, leaderboard and copy modules; `map.js` composes them with the existing layout. |
| 6. Totals and geographical scopes | Profiles use database totals independently of the loaded feed. `regions.py` supplies map configuration and backend posting bounds. |

The map still requires login, logout is available only from the viewer's own header profile icon with confirmation, and mobile Menu/Admin share a sheet while desktop drawers remain independent. Existing routes and product data were preserved; `GET /api/map-config` and `schema_migrations` were added.

Membership, local/guest permissions, polygons, region-filtered feeds and native apps were not implemented. The foundation keeps school and home ward independent for future communities; school membership does not imply ward membership. Leaflet and the tile service were unchanged.

Run backend, API-client and browser checks using the [testing guide](../TESTING.md#run-all-foundation-checks). Test data is disposable; restart the active application server to load backend changes.

Recorded results on 02/10/2026: 22 Python tests, the API-client check and all six browser suites passed after correcting the test's wait for the logout-error dialog. Browser suites covered general UI, interactive pins, Admin, mobile drawers, foundation contracts and logout. JavaScript syntax and the example map-configuration JSON also passed. Tests used Chrome/Chromium desktop/mobile viewports, not real iOS/Android devices.

## Earlier UI refactor record

This work addressed flows that had required repeated fixes. Existing APIs, database and product behavior were retained; it did not add communities, reports or a new login feature.

## Main changes

- Extracted CSS/JavaScript from both HTML pages. Typography, popup animation and profile components are shared under `assets/`.
- Centralized Menu/Admin state, mobile sheet height and button placement in `assets/js/map-layout.js`.
- Calculated map placement from an absolute geographical anchor instead of accumulating rounded pan steps. Sheet dragging uses displacement from the initial touch, preventing the sheet edge from jumping to the finger.
- Updated buttons, pin and map in the same layout cycle. Menu/Admin switching preserves geometry; resizing recalculates the visible map center.
- Kept profile presentation separate during fade-out. Late responses cannot overwrite another profile or reopen a closed panel.
- Reused Leaflet markers during refresh, preserved open popups and shared one popup event handler.
- Waited for image processing before posting. A new image selection invalidates the previous processing result.
- Shared WebP conversion and the Safari PNG fallback between pages. The backend uses the same validation/conversion for meme images and avatars.
- Closed SQLite connections after use; changed avatars transactionally and read the old image path before cleanup.
- Explicitly served each CSS/JS/icon asset. Responses have a single cache policy and frontend assets revalidate after reload.

## Backend checks

From the repository root, with `cwebp` on `PATH`:

```sh
python3 -m unittest discover -s tests -v
```

Coverage includes assets and permissions, authentication/profile/avatar/logout, pins/votes/Memerboard/admin deletion, image validation and SQLite connection cleanup. Databases and uploads are temporary, not live MemeMap data.

## Browser checks

`tests/check_browser.cjs` needs Node.js, Playwright and Chromium. Playwright is a testing tool, not a website runtime dependency.

Start the disposable fixture in one terminal:

```sh
python3 tests/serve_fixture.py
```

In another terminal, use the localhost URL printed by the fixture:

```sh
node tests/check_browser.cjs http://127.0.0.1:PORT
```

For installed macOS Chrome, set `MEMEMAP_TEST_BROWSER` to its executable. For Playwright outside the repo, set `NODE_PATH` to its `node_modules` directory.

Browser coverage includes the signed-in title, profile placement/fade-out, late profile responses, Menu/Admin switching, fixed-pin geometry, marker retention during refresh, resizing, repeated sheet dragging without eastward drift, mobile buttons, canvas WebP fallback and posting immediately after image selection. Public tile requests are blocked.

Checks used Chromium desktop/mobile viewports. Simulated image fallback does not replace Safari or real iPhone touch testing.

Stop the fixture with `Ctrl+C` to clean its temporary data. Restart the active MemeMap server to load backend and asset-routing changes.
